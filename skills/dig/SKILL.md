# Dig

プラン、設計ドキュメント、会話中の実装方針について、「書かれていないのに当然とされていること」を反復インタビューで炙り出す。目的は明確化ではなく前提への挑戦であり、ユーザーが「それは考えていなかった」と言う質問を引き出せたら成功とする。実装や修正は行わない。

構造化質問には、Claude Code では AskUserQuestion、Codex では request_user_input を使う。どちらも無い環境では、番号付き選択肢のテキスト質問で代替する。

## 全体方針

- 深く狭く掘る。1 つの糸を答えが出なくなるまで追ってから次に移り、広く浅いチェックリストは作らない
- 妥当に見える前提こそ疑う。どちらでもよい詳細の確認に質問枠を使わない
- 前提の分析と質問の設計は main agent が行う。何が重要で何がどうでもよいかの文脈を持つのは、会話中の main agent だけだからである。対象が巨大で裏取りが要る場合に限り、事実調査（コードの現状、仕様の記述、数値）だけをサブエージェントに委任する
- このスキルをサブエージェントや fork で実行しない。質問がユーザーに届かなくなるため

## 記録ファイル

`/tmp/dig/<slug>.md` を全ラウンドの台帳にする。slug は対象を表す短い英語スラッグとする。

```markdown
# Dig: <対象の1行説明>

## 対象
- <プランの所在（パス or 会話中の方針の要約）、ステートされたゴールと制約>

## 前提マップ
| # | 前提 | 分類 | リスク | 状態 |
<分類: 実現可能性 / ユーザー / スコープ / 依存 / 期間 / アーキテクチャ。リスク: high / medium / low。状態: 未検証 / 質問済み / 決定 / 保留>

## ラウンドログ
### Round <N>
- <質問と回答の要約>

## Decisions
| 論点 | 決定 | 理由 | リスク | 未解決事項 |
```

`/tmp` は永続しない作業用の台帳である。確定した決定は、終了時に GitHub Issue へ書き戻す（「最終サマリー」を参照）。リポジトリ内のファイルには書き込まない。

## 前提の分析

1. 対象を特定する（引数 → 会話文脈 → 直近のプラン提案の順）。対象、CLAUDE.md / AGENTS.md、対象が参照する仕様や設計ドキュメントを読み、記録ファイルの雛形を作る
2. 暗黙の前提を 6 分類で洗い出す。会話やプラン本文に明記済みの決定は状態「決定」で登録し、質問の対象から外す
3. 各前提に「間違っていた場合の被害の大きさ」でリスクを付け、前提マップに全件書く
4. 最高リスクの前提から、次のラウンドの質問を 2〜3 問作る。各質問の選択肢は 2〜4 個とし、選択肢ごとに trade-off を 1 行添える。CLAUDE.md / AGENTS.md の規約と矛盾する選択肢は作らない

## 質問ラウンド

上限は 3 ラウンドとする。

- 1 ラウンドは 2〜3 問に収める（Codex の request_user_input の上限が 3 問のため）
- どの選択肢が選ばれてもプランが変わらない質問は出さず、次の候補に差し替える
- 複数選択は「どの領域を掘るか」の絞り込みに限る。自由回答は環境側の「その他」入力で拾えるため、選択肢として用意しない

回答を得たら、ラウンドログと Decisions に追記する。次のラウンドは、回答が新たに露出させた前提のうち、最も深掘りに値する糸を 1 つ選んで作る。たとえば Round 1 で「WebSocket を選んだ」なら、Round 2 では「ステートレスな API サーバ 3 台でセッションをどう維持するか」を問う。前提マップの high リスク前提がすべて「質問済み / 決定 / 保留」になったら、それ以上の質問は作らない。

## 終了判定

次のいずれかで質問ラウンドを終える。

- high リスクの前提がすべて「質問済み / 決定 / 保留」になった
- 3 ラウンドに到達した
- ユーザーに質問疲れの兆候がある（回答が雑になる、「その他」で先に進めたい旨が書かれる等）

3 ラウンド到達時に未検証の high リスク前提が残っている場合だけ、「もう 1 ラウンド掘るか、残リスクとして記録して終えるか」を 1 問だけ聞く。延長は 1 回につき 1 ラウンドとする。

## 最終サマリー

記録ファイルの Decisions を確定させ、チャットには次だけを出す。記録ファイルの全文は再掲しない。

```markdown
## Dig サマリー

- 対象: <1行>
- ラウンド: <N> / 質問: <N> / 決定: <N>

### 最重要の発見
1. <ユーザーが考えていなかった論点トップ3>

### 残リスク
- <未解決のまま受け入れた前提。なければ「なし」>

### 推奨する次のアクション
1. <決定を受けてプランに反映すべきこと>

記録ファイル: /tmp/dig/<slug>.md
```

続けて、Decisions と残リスクを GitHub Issue に書き戻すかを 1 問だけ確認する。書き戻すと答えた場合は、対象に紐づく Issue があればコメントとして、無ければ新規 Issue として日本語で投稿し、URL を示す。この Issue が、別の PC やセッションで設計や実装を続けるときの引き継ぎ元になる。gh が使えない場合やユーザーが不要と答えた場合は、記録ファイルのパスを示して終える。

## 環境別の注意

- Claude Code：plan mode 中に呼ばれた場合は、ExitPlanMode でプランを提示する前に dig を実行し、決定をプランに反映してから提示する。具体的なコード案やレイアウト案を並べて比較させる質問に限り、option の preview を使う
- Codex：自由記述が欲しい選択肢には isOther を使う。`update_plan` はチェックリスト管理用であり、決定の記録先にしない
